# Дорожная карта State-LoveBot

VK-бот для администрирования Arizona RP: доступы, беседы, пулы, форум, конгресс, судебные роли.

**Версия документа:** июнь 2026  
**Текущая ветка архитектуры:** v2 (`main.py` — vkbottle + Tortoise ORM)

---

## Текущее состояние (v2)

### Готово и в эксплуатации

| Блок | Возможности |
|------|-------------|
| **Профиль** | `/me`, `/setnick`, `/who`, `/staff`, `/getid` |
| **Пулы** | `/pools`, `/createpool`, `/regchat`, `/msg` (с подтверждением) |
| **Модерация** | `/kick`, `/poolkick`, `/mute`, `/unmute`, `/del`, `/pin`, `/unpin` |
| **Беседа** | `/members`, приветствие при входе, `/rejoinkick` (on / ask) |
| **Админ беседы** | `/find`, `/online`, `/reg`, `/stitle`, `/chatsettings` |
| **ЦА** | `/setca`, `/regrole`, `/raccess`, авто-доступ в беседе след. ЦА |
| **Конгресс** | `/setspeaker`, `/setvice`, `/congress`, автоснятие ролей |
| **Судьи** | `/addcourt`, `/court`, `/rcourt`, `/removecourt` |
| **Пулы** | + `/unregchat` — отвязка беседы от пула |
| **Форум** | `/info`, `/edit`, `/fclose`, `/fopen`, `/fpin`, `/funpin`, `/иски` |
| **Инфра** | Docker, systemd, логи в ЛС админу, миграция из `users.db` |

### Известные ограничения

- **Legacy** (`legacy/forum_bot.py`) — повестки `/notif`, `/res`, часть судебного UI ещё только там.
- **Схема БД** — в основном `generate_schemas(safe=True)` + точечные `ALTER`; полноценный цикл Aerich не зафиксирован.
- **`/reg`** — дата VK через foaf / оценка по ID; официального поля в API нет.
- **`VK_USER_TOKEN`** — опционален; без него `/members` и `/msg` могут видеть неполный список участников.
- **События VK** — выход из беседы приходит как `chat_kick_user` (`from_id == member_id`); обработка через raw longpoll.
- **README** — таблица уровней устарела относительно реального `/help`.

## Организационная модель (глобальное видение)

> **Решение (июнь 2026):** полные «сферы» (МЮ, МО, МЗ…) откладываем. Сейчас в коде — **только ЦА**: флаг `has_ca_access`, беседа след. ЦА, единая `/regrole`. МЮ/МО и т.д. — в фазе 5+.

### Реализовано сейчас — доступ ЦА

| Механизм | Команда / событие | Поведение |
|----------|-------------------|-----------|
| Ручная выдача | `/setca [@user\|ник] [off]` | Флаг `has_ca_access` на сервере |
| Беседа след. ЦА | `/regrole sledca` (алиас `/regsledco`) | Вход → ур. 1 + доступ ЦА; выход/кик → снятие |
| Регистрация ролей | `/regrole court\|congress\|sledca` | Вместо отдельных `/regcourt`, `/regcongress`… |
| Ограничение ур. 1–4 | конгресс, суд, `/regrole` | Нужен доступ ЦА; **ур. 5+** — без флага |
| Отвязка пула | `/unregchat` | Снимает `pool_id` и алиас с текущей беседы |
| Резолв пользователя | везде через `VKResolver` | VK-ссылка / id / **ник из `/setnick`** (частичное совпадение) |

Бот обслуживает **две пересекающиеся оси** власти Arizona RP. Их нужно явно описать в коде и в командах, иначе доступы разъезжаются между уровнями 1–10, форумными ролями и «сферами» (МЮ, МО, ЦА…).

| 2 | SUPERVISOR | Следящий | Мут, pin, `/del`, назначение судей (`/addcourt`) |
| 3 | ZGS | ЗГС | Kick, `/rejoinkick`, `/setlevel`, конгресс, судебные беседы |
| 4 | GS | ГС | Расширенная модерация, управление беседами |
| 5 | ZGS_GOS | ЗГС ГОС | Госсоветы, пулы (создание), межведомственные беседы |
| 6 | GS_GOS | ГС ГОС | То же + стратегические решения по ГОС-структурам |
| 7 | CURATOR | Куратор | Кросс-сферный надзор |
| 8 | ZGA | ЗГА | Почти полный доступ к форуму и staff |
| 9 | GA | ГА | Верхний staff |

**Сфера в бейдже** (например «ЗГС **ЦА**») сейчас **не хранится в БД** — в `format_actor_badge` только уровень без привязки к ведомству. Это целевой пробел (см. фазу 5).

### Ось 2 — Форумные / организационные роли

Отдельные boolean-флаги и привязки бесед (`role_chats`). Не заменяют уровень 1–10, а **дополняют** его для форума и узких сценариев.

| Роль (`ForumRoleKey`) | Сокращение | Беседа (legacy → v2) | Форум / сценарий |
|------------------------|------------|----------------------|------------------|
| `judge` | Судья | `/regcourt` ✅ | Раздел судей, `/иски`, повестки |
| `attorney` | Адвокат | `/regatt` ❌ legacy | Раздел 3287 |
| `leader` | Лидер | `/regleader` ❌ legacy | Разделы МЮ (2935–2945 и др.) |
| `admin` | Админ | `/regadmin` ❌ legacy | Админ-раздел, эскалация в беседу админов |
| `ministry_of_justice` | МЮ | `/regmy` ❌ legacy | Постановления из судебных дел → МЮ |
| `congress` | Конгресс | `/regrole congress` ✅ | Спикер / вице, автоснятие при выходе |
| `sled_ca` | След. ЦА | `/regrole sledca` ✅ | Авто ур. 1 + `has_ca_access` при входе |

✅ — есть в v2 · ❌ — пока только в `legacy/main.py`.

### Ось 3 — Сферы (ведомства) Arizona RP

**Сфера** — логическая единица госструктуры: свой пул бесед, форумные разделы, лидеры, опционально свой минимальный уровень для команд.

Черновой реестр (по `legacy/config_legacy.py` и практике сервера):

| Сфера | Полное название | Примеры форум-разделов | Беседы / пулы (идея) |
|-------|-----------------|------------------------|----------------------|
| **ЦА** | Центральная администрация | Админ-раздел, тех | Staff, следящие, общий пул ЦА |
| **МЮ** | Ministry of Justice | FBI, LSPD, SWAT, RCSD… | `/regmy`, пул «силовые МЮ» |
| **МО** | Ministry of Defence | Армия LS/SF, тюрьма LV | Отдельный пул МО |
| **МЗ** | Medical Centers | LSMC, LVMC, пожарные | Пул медиков |
| **ГОС** | Правительство | Кабинет губернатора, сенат, партии | Пулы 5–6 ур., конгресс |
| **Суд** | Судебная власть | Иски, судебные дела | `/regcourt`, повестки |
| **АК** | Адвокатская коллегия | Раздел 3286 | `/regatt` |
| **Прочие** | Минсоц, лицензии, радио… | По мере необходимости | Точечные пулы или алиасы |

Связь **сфера ↔ пул**: пул — техническая группа VK-бесед; сфера — организационный смысл. Один пул может обслуживать одну сферу; крупная сфера (МЮ) — несколько пулов (FBI, LSPD…).

### Как это должно работать вместе (целевая модель)

```text
Сервер (server_id)
├── Уровни 1–10 (UserServerAccess)     → кто может /kick, /createpool…
├── Сфера (sphere_id)                  → ЦА, МЮ, МО… — опционально у каждого user
│   └── Делегирование внутри сферы     → «ЗГС МЮ» может выдавать роли только в МЮ
├── Роли (judge, leader…)              → форум + узкие команды
├── role_chats                         → одна беседа на роль / на сферу
└── pools + chats                      → массовые /msg, poolkick по ведомству
```

**Матрица доступа** (цель — одна таблица в коде / конфиге, не размазанная по middleware):

| Действие | Мин. уровень | Роль / сфера | Где живёт сейчас |
|----------|--------------|--------------|------------------|
| `/kick` | 3 (ЗГС) | — | `requires_level` |
| `/regcourt` | 3 + court_manager | — | `forum_access` |
| `/addcourt` | 2 + court_manager для reg* | — | смешано |
| Форум `/info` | forum role или 8+ | judge / leader / attorney | `ForumAccessChecker` |
| `/createpool` | 5 | желательно привязка к сфере | только уровень |
| Постановление → МЮ | judge | `ministry_of_justice` chat | legacy only |

### Текущие разрывы (as-is → to-be)

1. **Сфера не в БД** — нельзя вывести «ЗГС МЮ» в `/staff` и фильтровать команды по ведомству.
2. **Роли лидер / адвокат / админ / МЮ** — флаги есть, команды `/regleader`, `/regatt`, `/regadmin`, `/regmy` не перенесены в v2.
3. **Два бота** — судебный UI и повестки в legacy; staff-команды в v2.
4. **Пулы без сферы** — `/pools` не показывает «это пул МЮ»; `/createpool` не требует указания ведомства.
5. **Конгресс** — отдельный модуль, но не вписан в общую матрицу сфер.
6. **Автоснятие ролей** — работает для congress + court; для leader/attorney/admin — логика в legacy.

## Фаза 5 — Сферы МЮ/МО/МЗ и расширение матрицы (2–4 месяца)

Цель: после стабилизации **ЦА** (см. таблицу выше) — вынести МЮ, МО, МЗ и др. по той же схеме, что `sled_ca`, без переписывания ядра.

| # | Задача | Описание |
|---|--------|----------|
| 5.1 | **Модель `Sphere`** | `id`, `code` (CA, MJ, MO, MZ, GOS…), `name`, `server_id`, опционально `min_level_override` |
| 5.2 | **`UserSphere`** | Привязка пользователя к сфере(ам): основная + дополнительные; отображение в `/me`, `/staff`, бейджах |
| 5.3 | **Пул ↔ сфера** | Поле `sphere_id` у `Pool`; `/createpool МЮ следящие` или `/createpool --sphere MJ` |
| 5.4 | **Перенос role-регистраций** | `/regleader`, `/regatt`, `/regadmin`, `/regmy` → v2; единый `/regrole <роль>` |
| 5.5 | **Расширение `ForumRoleKey`** | Явные коды под сферы или маппинг `leader` → сфера МЮ; документировать в `/help` |
| 5.6 | **`AccessMatrix` в коде** | Один модуль: команда → (min_level, roles[], spheres[], chat_types[]) |
| 5.7 | **Делегирование** | ЗГС сферы может `/setlevel` только внутри своей сферы (опционально, по флагу сервера) |
| 5.8 | **Журнал по сферам** | action_logger: тег `sphere` в событиях kick, setlevel, regrole |
| 5.9 | **`/spheres` / `/mysphere`** | Список ведомств, кто в какой сфере, какие пулы и беседы привязаны |
| 5.10 | **Постановления МЮ** | Перенос из legacy: дело → беседа МЮ + пинг лидеров в беседе |

**Критерий готовности:** новый сотрудник по `/help` и `/spheres` понимает уровень, сферу и роль; legacy role-команды отключены.
