# ТЗ: веб-панель State-LoveBot

**Статус:** черновик  
**Дата:** июнь 2026  
**Связь с ботом:** v2 (`main.py`, Tortoise ORM, VK Long Poll)

---

## 1. Цель и задача

Сейчас весь конфиг и операционное управление — через `.env`, VK-команды и прямой доступ к БД. Это неудобно для:

- смены настроек без рестарта и SSH;
- просмотра staff, пулов, бесед, логов в одном месте;
- делегирования (разработчик / ЗГС+ без выдачи ур. 10 в VK);
- подготовки к мульти-серверу и сферам (см. backlog).

**Цель:** веб-сайт (админ-панель), через который управляют ботом и смотрят состояние системы без правки файлов на сервере.

**Не цель MVP:** публичный лендинг, личный кабинет игроков, замена VK-команд полностью.

---

## 2. Пользователи и доступ

| Роль | Кто | Мин. доступ |
|------|-----|-------------|
| **Разработчик** | ур. 10 в БД бота | Всё |
| **Админ сервера** | ур. 8–9 (ЗГА/ГА) | Просмотр + часть настроек сервера |
| **Оператор ЦА** | ур. 5–7 + `has_ca_access` | Staff, пулы, роли ЦА (без секретов) |
| **Только чтение** | опционально, отдельный флаг | Дашборд, логи, staff |

### Авторизация (рекомендация)

1. **VK OAuth** (или VK ID) — вход по VK-аккаунту.
2. После входа бэкенд сверяет `vk_id` с `User` / `UserServerAccess` в той же БД, что у бота.
3. Сессия: JWT/httpOnly cookie, TTL 24 ч.
4. Разработчик (ур. 10) — полный доступ; остальные — матрица по разделам (см. §6).

**Альтернатива MVP:** один `ADMIN_PANEL_TOKEN` в `.env` + пароль (быстрее, хуже для команды).

## 3. Архитектура

```text
┌─────────────┐     HTTPS      ┌──────────────────┐
│  Браузер    │ ◄────────────► │  Web (Frontend)  │
└─────────────┘                └────────┬─────────┘
                                        │ REST / WS
                               ┌────────▼─────────┐
                               │  Panel API       │
                               │  (FastAPI)       │
                               └────────┬─────────┘
                    ┌───────────────────┼───────────────────┐
                    │                   │                   │
             ┌──────▼──────┐    ┌───────▼───────┐   ┌───────▼───────┐
             │  bot.db     │    │  Redis (опц.) │   │  VK Bot       │
             │  (Tortoise) │    │  кэш / очередь│   │  (main.py)    │
             └─────────────┘    └───────────────┘   └───────────────┘
```

### Принципы

- **Одна БД** с ботом (`DATABASE_URL`) — панель не ведёт свой источник правды.
- Секреты (`VK_GROUP_TOKEN`, `VK_USER_TOKEN`, forum cookies) — **только на бэкенде**, в UI маска `••••••` + «заменить».
- Изменения чувствительных настроек → запись в `panel_audit_log` + опционально дубль в VK-логи бота.
- Бот и API — **разные процессы**; общая схема через Tortoise/Aerich.

### Стек (предложение)

| Слой | Вариант |
|------|---------|
| API | FastAPI + Tortoise ORM (те же модели) |
| Frontend | React/Vite или Vue — дашборд, таблицы, формы |
| Деплой | nginx reverse proxy, тот же VPS что бот |
| Realtime логи | SSE или polling `/api/logs/stream` |

## 4. Разделы сайта (карта)

### 4.1. Дашборд

- Статус бота: online / last event / uptime (heartbeat от `main.py` или проверка Long Poll).
- Счётчики: пользователей в БД, staff (ур. 1+), судьи, бесед в пулах.
- Последние 10 действий из логов (как в `ActionLogger`).
- Быстрые ссылки: «беседа логов», «форум OK/ошибка».

### 4.2. Настройки (Settings)

Перенос из `.env` в UI с сохранением в БД (`panel_settings` или `server_settings` JSON).

| Группа | Поля | Кто меняет |
|--------|------|------------|
| **VK** | `VK_GROUP_ID`, `VK_GROUP_TOKEN`*, `VK_USER_TOKEN`* | Разработчик |
| **Сервер** | `DEFAULT_SERVER_SLUG`, `DEFAULT_SERVER_NAME`, `SERVER_NUMBER`, `SERVER_TAG` | Разработчик |
| **Форум** | `FORUM_BASE_URL`, cookies `xf_*`, `FORUM_USER_AGENT` | Разработчик |
| **Логи** | fallback `LOG_CHAT_ID`, `LOG_LEVEL` | Разработчик |
| **Поведение** | шанс random reaction (5%), включить welcome/kick в чат | Разработчик |
| **Форум-разделы** | `JUDGE_FORUM_ID`, `LEADER_ALLOWED_FORUMS` (список id) | Разработчик / ЗГА |

\* Токены не показывать целиком после сохранения.

**Поведение при сохранении:**

- Запись в БД + синхронизация в `.env` (опционально) **или** бот читает настройки из БД при старте и по webhook «reload».
- Критичные поля (токен VK) — рестарт бота с кнопки «Применить и перезапустить» (только разработчик).

### 4.3. Серверы

Таблица `servers`:

- slug, name, `is_active`, **`log_peer_id`** (беседа логов — аналог `/regchat logs`).
- CRUD для мульти-сервера (сейчас один default).

### 4.4. Пользователи и доступы

**Список** (`/staff` в вебе):

- Фильтр: уровень, ЦА, роль (судья, спикер…), поиск по нику / vk_id.
- Карточка пользователя:
  - ник, vk_id, уровень на сервере, `has_ca_access`, форумные флаги;
  - история: кто выдал уровень (`granted_by`), дата;
  - действия: изменить уровень (0–9), вкл/выкл ЦА, снять роли (аналог `/raccess` с ограничениями).

**Ограничения как в боте:**

- Нельзя выдать уровень выше своего.
- `/raccess`-логика: не снимать с равного/выше.
- Ур. 10 только через `MAIN_ADMIN_ID` / разработчик.

### 4.5. Пулы и беседы

| Экран | Данные | Действия |
|-------|--------|----------|
| Пулы | `pools` | создать, переименовать, удалить (как `/createpool`) |
| Беседы | `chats` + привязка к пулу | привязать/отвязать, алиас, peer_id, название |
| Настройки беседы | `chat_peer_settings` | `rejoin_kick`: off / on / ask |

Визуализация: пул → список бесед (как `/pools`, но деревом).

### 4.6. Организационные роли

Привязки без сфер (текущий бот):

| Тип | Модель | UI |
|-----|--------|-----|
| Судьи | `is_judge` | список, добавить/снять |
| Конгресс | спикер / вице | назначить, снять |
| Role chats | `role_chats` | court, congress, sled_ca — peer_id |
| ЦА | `has_ca_access`, sled_ca peer | флаги + беседа |

*(Фаза 2: сферы — см. `docs/sphere-conferences.md`, если документ восстановят.)*

### 4.7. Логи действий

- Лента событий (те же поля, что `ActionLogger`: кто, где, цель, итог, время).
- Фильтры: дата, action, user_id, peer_id, только ошибки.
- Экспорт CSV.
- Источник MVP: **новая таблица** `action_log_entries` (бот пишет дубль при `log_user`); чтение из VK-чата логов — ненадёжно.

### 4.8. Модерация (опционально фаза 2)

- История `moderation_repo` (kick, poolkick).
- Муты, если появятся в БД.

### 4.9. Форум

- Статус подключения (тест cookies).
- Кнопка «Проверить форум» (как `scripts/test_forum_connect.py`).
- Без редактирования тем из панели в MVP (остаётся в VK).

### 4.10. Документация внутри панели

- Встроенный `/help` и `/devhelp` (markdown из `help_menu.py`).
- Ссылка на deploy-инструкцию.

## 5. API (черновик эндпоинтов)

```text
POST   /api/auth/vk              # OAuth callback
GET    /api/me                   # текущий пользователь + права

GET    /api/dashboard/stats
GET    /api/settings             # маскированные секреты
PATCH  /api/settings             # разработчик
POST   /api/settings/reload-bot  # сигнал reload

GET    /api/servers
PATCH  /api/servers/{id}         # log_peer_id, name

GET    /api/users?q=&level=
GET    /api/users/{vk_id}
PATCH  /api/users/{vk_id}/access # level, has_ca_access
POST   /api/users/{vk_id}/revoke-roles

GET    /api/pools
POST   /api/pools
GET    /api/pools/{id}/chats
PATCH  /api/chats/{peer_id}      # pool, alias
PATCH  /api/chats/{peer_id}/settings  # rejoin_kick

GET    /api/role-chats
PATCH  /api/role-chats/{role}

GET    /api/logs?from=&to=&action=
GET    /api/logs/export.csv

GET    /api/forum/status
POST   /api/forum/test
```

Все `PATCH/POST` — с `X-Request-Id` и записью в audit.

## 8. UI/UX требования

- Тёмная тема по умолчанию (долгие смены админов).
- Таблицы: сортировка, поиск, пагинация 50.
- Формы: подтверждение на удаление / смену токена / mass poolkick.
- Тосты об успехе; ошибки API — человекочитаемо на русском.
- Мобильная вёрстка **не обязательна** в MVP (desktop-first).
- Язык интерфейса: **русский**.

---

## 9. Безопасность

- HTTPS only, HSTS.
- Rate limit на `/api/auth` и `/api/settings`.
- CSRF для cookie-сессий.
- Токены VK и forum cookies **никогда** в ответах API целиком.
- Логи панели не содержат секретов.
- IP allowlist (опционально) для `/api/settings`.
- 2FA для разработчика — фаза 2.

## 11. Критерии приёмки MVP

1. Разработчик входит в панель и видит дашборд без SSH.
2. Список staff совпадает с `/staff` в VK (±формат).
3. Логи за последние 7 дней доступны в вебе с фильтром по action.
4. Можно сменить `rejoin_kick` беседы из UI — бот подхватывает без правки кода.
5. Секреты не утекают в Network tab (только маска).
6. Действия в панели дублируются в VK-логи (если настроен `/regchat logs`).
