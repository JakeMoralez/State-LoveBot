# Проверка обновления cookies форума

Изменения нужны в обоих проектах: State-LoveBot обрабатывает cookies, State-LoveAdmin
показывает результат. После обновления бота новые cookies проверяются в отдельном
подключении. Только успешная авторизация и запись файла заменяют текущую сессию.
При ошибке предыдущие cookies и подключение сохраняются.

Сохранённый в `forum_cookies.json` набор используется целиком. `.env` используется
только при отсутствии полного сохранённого набора. Пустой `xf_tfa_trust` в форме
не заполняется старым значением из `.env`.

Форма также принимает `__Host-l7_clearance` (проверка браузера) и `xf_csrf`.
Если они есть в браузере, копируйте их из той же сессии, что и остальные cookies.
Бот передаёт их библиотеке и сохраняет актуальные значения из cookie jar после
успешного подключения. Наличие cookie проверки браузера не гарантирует, что
форум разрешит запросы с другого сервера.

## Диагностика на сервере

Из каталога бота запустите его рабочим Python (путь зависит от установки):

```sh
.venv/bin/python scripts/diagnose_forum_session.py
```

Скрипт делает только GET-запросы, не меняет файл cookies и не выводит их значения.
Он показывает версию установленной библиотеки, названия отправленных cookies,
HTTP-статусы и совпадение значений с исходным набором перед каждым запросом.
Так можно сравнить запросы до обработки антибота и запрос `/account/` после неё.
Изменение `xf_session` может быть нормальной ротацией сессии.

Если `/account/` получает 401 при наличии ожидаемых cookies, это подтверждает
отказ форума на запрос с сервера, но само по себе не определяет его причину.
Успешная проверка из браузера не заменяет проверку из окружения бота.

## Локальные проверки

```sh
.venv/bin/python -m unittest discover -s tests -p test_forum_session.py -v
```

Проверки используют временный файл, подставной API и локальный HTTP-сервер.
Рабочие cookies и внешний форум не используются.
