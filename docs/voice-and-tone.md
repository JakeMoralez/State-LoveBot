# Voice & Tone — единый стиль ответов (панель + бот)

> Общий гайд по текстам для **State Love Admin** и **State-LoveBot**.
> Цель: чтобы сообщения об успехе, ошибках и подсказки везде звучали одинаково,
> по-человечески и помогали пользователю, а не пугали его техническими деталями.

## 1. Принципы

1. **С точки зрения пользователя.** Называем вещи так, как их видит человек
   («уровень доступа», «беседа», «тема на форуме»), а не так, как устроен код
   (`access_level`, `peer_id`, `thread_id`).
2. **Активный залог, sentence case.** «Укажите уровень доступа», а не
   «Уровень доступа должен быть указан». Первая буква заглавная, остальное как в
   обычном предложении. Без КАПСА и без Title Case.
3. **Ошибка = что случилось + что делать.** Сначала суть, затем подсказка, как
   починить. Без «извините» и без «сервер вернул 500».
4. **Коротко и конкретно.** Одна мысль — одна строка. Никакой воды и канцелярита.
5. **Единая терминология.** Одно и то же называем одинаково во всех местах
   (см. §4). Кнопка «Сохранить» → тост «Сохранено».
6. **Без утечки внутренностей.** Пользователю не показываем трейсбеки,
   `{exc}`, имена переменных, названия таблиц и HTTP-коды.

## 2. Структура сообщения

```
<глиф> <суть: что произошло>
<подсказка: что делать дальше>   ← опционально
```

Пример плохо → хорошо:

- ❌ `Internal Server Error` → ✅ `Что-то сломалось на нашей стороне. Попробуйте ещё раз через минуту.`
- ❌ `Укажите access_level` → ✅ `Укажите уровень доступа.`
- ❌ `Не удалось закрепить: {exc}` → ✅ `Не получилось закрепить сообщение. Проверьте права бота в беседе.`

## 3. Статус-глифы (канон)

Общий набор эмодзи-статусов. В боте они ведущие (первый символ строки), в панели
им соответствуют цветовые варианты компонентов `Alert`/`Toast`.

| Глиф | Значение | Панель (вариант) |
|------|----------|------------------|
| `⛔` | Нет доступа / запрещено | `danger` |
| `❌` | Ошибка / неверный ввод | `danger` |
| `✅` | Успех | `success` |
| `⚠️` | Предупреждение | `warning` |
| `ℹ️` | Информация | `info` |
| `📭` | Пусто (нет данных) | пустое состояние |
| `⚙️` | В процессе / выполняется | `info` / индикатор |

Правила: **ровно один пробел** после глифа; **один глиф** на сообщение (не
дублируем в начале и в конце).

## 4. Терминология (единый словарь)

| Пишем так | Не пишем |
|-----------|----------|
| уровень доступа | access_level, ур. доступа |
| беседа | чат, peer, диалог |
| участник | юзер, member |
| тема на форуме | thread, тред |
| сфера | scope, sphere (в тексте для пользователя) |
| задача | таск, task |
| вход на портал | авторизация, логин (в тексте) |

Ранги 1–11 называем их именами (ПС, Следящий, ЗГС, ГС, Куратор, ЗГА, ГА,
Разработчик и т.д.) — они уже привычны аудитории.

## 5. Пустые состояния и загрузка

- Пусто — это приглашение к действию: `📭 Пулы ещё не созданы. Создайте первый: /addpool <название>`.
- Загрузка — коротко и без точки-многоточия-ада: «Загрузка…».

## 6. Реализация

- **Бот:** используйте хелперы `services/responses.py`
  (`success/error/denied/empty/working/info/warn`) вместо ручной склейки
  `"❌ " + text`. Доменные ошибки — через `packages/domain/errors.py`.
- **Панель (бэкенд):** человечные строки в `backend/app/services/messages.py`,
  формат ответа `{"detail": ...}` не меняем.
- **Панель (фронт):** единые компоненты `Alert`/`Toast`; никаких `window.alert()`
  и сырых `text-red-400`.
